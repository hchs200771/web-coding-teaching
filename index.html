02 · VS Code 安裝與介紹

下載 VS Code

  1. 打開瀏覽器，到 code.visualstudio.com。
  2. 按藍色的下載按鈕。網站會自動選好你的系統。
  3. 到「下載」資料夾，雙擊剛下載的安裝檔。

檔名像 VSCodeUserSetup-x64-….exe。這是 User Installer，不用管理員權限。

下載的是 .zip。解開後，把 Visual Studio Code 拖進「應用程式」資料夾。

只從官網下載。搜尋結果裡的其他下載站可能夾帶廣告軟體。

02 · VS Code 安裝與介紹

安裝時要勾的選項

一路按「下一步」。到「選取其他工作」這頁，確認下面都有勾：

  1. 將「以 Code 開啟」動作加入 Windows 檔案總管檔案的操作功能表。
  2. 將「以 Code 開啟」動作加入 Windows 檔案總管目錄的操作功能表。
  3. 加入 PATH（重新啟動後生效）。這個最重要，預設已經勾好。

前兩個讓你在資料夾上按右鍵，就能用 VS Code 打開。最後勾「啟動 Visual Studio Code」，按完成。

02 · VS Code 安裝與介紹

第一次打開：換成中文

右下角通常會跳出「安裝語言套件」的提示，直接按安裝並重新啟動。沒看到的話：

  1. 按 Ctrl+Shift+X 打開延伸模組（Extensions）。
  2. 搜尋 Chinese (Traditional)，安裝 Microsoft 出的那一個。
  3. 按右下角的 Change Language and Restart。

裝好了畫面還是英文，就手動指定顯示語言：

  1. 按 Ctrl+Shift+P 打開命令選擇區，輸入 display。
  2. 選 Configure Display Language（設定顯示語言）。
  3. 選「中文(繁體) zh-tw」，再按 Restart 重新啟動。

歡迎頁可以直接關掉。想換深色或淺色外觀：Ctrl+K 放開，再按 Ctrl+T。

02 · VS Code 安裝與介紹

打開一個資料夾

VS Code 一次打開「一整個資料夾」。一個網站就是一個資料夾。

  1. 上方選單選「檔案 → 開啟資料夾」。
  2. 先選「文件」資料夾試試看，按「選擇資料夾」。
  3. 問「是否信任此資料夾中檔案的作者」：自己的資料夾就按「是，我信任作者」。

從別人那裡下載、不確定的資料夾，先選「否，我不信任」，只看不執行。

02 · VS Code 安裝與介紹

VS Code 畫面的五個區塊

  1. 活動列：最左邊一排圖示。檔案總管、搜尋、原始檔控制（Git）、延伸模組都從這裡切換。
  2. 側邊欄：點活動列的圖示就換內容。最常用檔案總管，看資料夾裡有哪些檔案。Ctrl+B 收起或打開。
  3. 編輯區：點檔名就在這裡打開，上方是分頁。分頁上有白點代表還沒存，按 Ctrl+S 存檔。
  4. 面板：終端機住在這裡。Ctrl+` 打開或收起。
  5. 狀態列：最底下一條。左邊顯示目前的 Git 分支，右邊顯示游標在第幾行。

最上面一條是選單列（File、Edit、View…），設定和開新視窗從這裡找。

忘記功能在哪：Ctrl+Shift+P 打開命令選擇區，直接打字搜尋。Ctrl+P 用檔名找檔案。

02 · VS Code 安裝與介紹

在 VS Code 打開終端機

終端機（terminal）是用打字下指令的視窗。VS Code 下方的面板就有一個，Windows 預設是 PowerShell。

  1. 按 Ctrl+`（Esc 下面那顆鍵），或從上方選單選「終端機 → 新增終端」。
  2. 畫面下方會出現終端機面板。
  3. 看到下面這行，就可以輸入指令。
PS C:\Users\你的名字>

這行提示像地址牌：告訴你現在在哪個資料夾。PS 表示這裡是 PowerShell。

之後投影片寫「在 PowerShell 輸入」，就是貼在這個終端機裡。

03 · Claude Code 安裝與試用

安裝 Claude Code

在 VS Code 的終端機（PowerShell）貼上 Windows PowerShell 這一格。

irm https://claude.ai/install.ps1 | iex
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
curl -fsSL https://claude.ai/install.sh | bash

需要 Claude Pro / Max 訂閱或 Console 帳號（API 預付費）；Team / Enterprise 也可。 免費 claude.ai 帳號不含 Claude Code。

Windows 10 1809 以上或 Windows 11、至少 4GB 記憶體與網路。 不用管理員權限，也不用先裝 Git，等一下的 Git 第一章才裝。原生安裝會自動更新。

這裡大概要等 5 到 10 分鐘。下載時畫面不會動、也沒有進度條，下載完才會出現下面的文字。不要關掉視窗。 

Setting up Claude Code...

Installing Claude Code native build latest...

出現這兩行代表正在安裝，再等它跑完。完成後把 VS Code 整個關掉重開。

看到「The token '&&' is not a valid statement separator」：把 CMD 指令貼進 PowerShell 了。 看到「'irm' is not recognized」：把 PowerShell 指令貼進 CMD 了。

03 · Claude Code 安裝與試用

卡關：無法辨識 claude

claude : 無法辨識 'claude' 詞彙是否為 Cmdlet、函數、指令檔或可執行程式的名稱。

程式裝好了，但電腦不知道去哪裡找它。在終端機依序執行這兩行：

  1. 把 Claude Code 的位置加進 PATH（電腦找程式的路線清單）：
[Environment]::SetEnvironmentVariable('Path', [Environment]::GetEnvironmentVariable('Path', 'User') + ";$HOME\.local\bin", 'User')
  1. 用完整路徑啟動 Claude Code，現在就能用：
& "$HOME\.local\bin\claude.exe"

下次把 VS Code 整個關掉重開後，直接打 claude 就可以。 第二行如果顯示找不到檔案，代表安裝沒跑完，回到「安裝 Claude Code」重裝。

03 · Claude Code 安裝與試用

第一次登入：授權流程

claude
  1. 選喜歡的外觀主題，用上下方向鍵選，Enter 確認。
  2. 選登入方式：選 Claude 帳號（Claude account with subscription），不是 Console。
  3. 瀏覽器會自動打開 Claude 的授權頁。還沒登入就先登入有訂閱的帳號。
  4. 頁面列出 Claude Code 會用到的權限，例如存取 Claude Code 工作階段、代表你上傳檔案。拉到最下面，按「授權」。
  5. 回到 VS Code 的終端機，看到登入成功，按 Enter 繼續。
  6. 問是否信任這個資料夾（trust this folder）：自己的資料夾選 Yes。

瀏覽器沒有自動打開：按住 Ctrl 點終端機裡的網址。授權頁給你一串代碼的話，複製後貼回終端機，按 Enter。 登入一次就會記住，之後不用再登入。

看到「API Error: 400 We've updated our Consumer Terms and Privacy Policy」：條款更新了。 在剛剛按「授權」的那個瀏覽器打開 claude.ai（同一個帳號）， 在跳出的視窗按同意，再回終端機重新問一次。沒有跳出視窗：在 Claude Code 輸入 /logout， 再打 claude 重新登入。

狀態列（status line）像儀表板。在底下顯示目前模型、資料夾、Git 分支。

03 · Claude Code 安裝與試用

設定 3：權限模式與安全

Shift+Tab 切模式。先看底下的名稱，練習時切到 manual mode。

manual / default（預設）

⏸ manual mode on：改檔、跑指令前先問你。新手先用這個。

accept edits（接受編輯）

⏵⏵ accept edits on：改檔與簡單檔案指令不再逐次問。

plan（計畫）

⏸ plan mode on：只看、只規劃，不修改。

auto（自動）

⏵⏵ auto mode on：另一個模型代你檢查動作。新版可能從這個模式開始。

/permissions

在 Claude Code 裡查看允許、詢問與拒絕的規則。

看清楚授權提示再按一般的 Yes。先不要選「Yes, and don’t ask again」。 不懂就問它「這個指令會做什麼？」平常電腦不要用略過權限（bypassPermissions）。

Esc 中斷；空白輸入列連按兩次 Esc 可回到之前（rewind）。 這能復原 Claude 的檔案編輯，但不能復原指令搬動、刪除的檔案，也不能代替 Git。

09 · 課後：用自己的網域上線

為什麼我需要學這個？

問Lovable 已經給我一個網址，為什麼還要用自己的網域、自己部署？

答客人看到「你的名字.com」比一串 lovable.app 更專業、好記，名片和 Instagram 也放得下。學會自己部署，網站放在哪裡由你決定，不被單一平台綁住；GitHub Pages 放靜態網站本身不用錢，只要付網域的年費。

學完這章，你可以：讓客人打你自己的網域就看到網站，而且有 https 鎖頭。

09 · 課後：用自己的網域上線

先看整體：要設定三個地方

網域商（DNS）→ GitHub Pages→ 你的網站

GitHub Actions 會在每次 push 到 main 時，自動把網站建置（build）並發布。網域商那邊的 DNS 負責把「你的網域」指到 GitHub。

  1. 驗證網域。
  2. 讓 GitHub 建置網站。
  3. 在 GitHub 填網域。
  4. 到網域商設定 DNS。
  5. 檢查並開 HTTPS。

先決條件：Lovable 建立的 repo 是私人的；GitHub 免費方案只能用「公開」repo 開 Pages。二選一：把 repo 改成公開（Settings → General 最下面 Danger Zone → Change visibility；原始碼大家都看得到，不能放密碼或金鑰），或升級 GitHub Pro。

Lovable 付費方案也能直接在 Lovable 綁網域；這章講 GitHub Pages 的做法，同一個網域只選一邊指過去。

步驟 1：先驗證網域（找到按鈕）

這裡是「個人設定」，不是 repo 設定。驗證可以防止別人把你的網域拿去用在他的 GitHub Pages。

先點右上角你的頭像 → Settings。

  1. 左邊選單往下捲到 Code, planning, and automation，點 Pages。
  2. 在 Verified domains 按綠色的 Add a domain。

09 · 課後：用自己的網域上線

步驟 1：先驗證網域（加 TXT 紀錄）

  1. 輸入 你的網域.com（不要加 www、不要加 https://）→ Add domain。
  2. 畫面會出現一筆 TXT 紀錄，先不要關。名稱是 _github-pages-challenge-你的帳號，值照畫面複製。
  3. 到網域商的 DNS 設定新增這筆 TXT，等生效後回來按 Verify。

有的網域商會自動接上網域，有的要打完整的 _github-pages-challenge-你的帳號.你的網域.com。

這筆 TXT 驗證完也不要刪，刪了會失去驗證。生效最久可能要 24 小時；離開頁面後，可在網域旁的 ⋯ 選 Continue verifying。

09 · 課後：用自己的網域上線

workflow 和 action 是什麼

GitHub Actions 是 GitHub 提供的「雲端自動化機器人」：你 push 之後，GitHub 借一台雲端電腦，照你寫好的步驟自動做事。

workflow（工作流程）

一份工作清單，寫在 repo 裡的 .github/workflows/ 資料夾，副檔名 .yml。裡面寫「什麼時候做」（例如 push 到 main）和「依序做哪些步驟」。

action（現成的步驟）

別人寫好、可以直接拿來用的一個步驟，像樂高積木。例如 actions/checkout 負責把你的程式碼下載到雲端電腦，actions/deploy-pages 負責發布到 GitHub Pages。@v7 這種寫法是指定版本。

run（自己下指令）

不用現成積木，直接寫要執行的指令，就像你在終端機打 npm run build。

可以想成一張食譜：workflow 是整張食譜，每一步不是用現成調理包（action），就是自己動手（run）。

每次跑完會在 repo 的 Actions 分頁留下紀錄；公開 repo 使用 GitHub Actions 免費，私人 repo 每月有免費額度，這種小網站通常用不完。

09 · 課後：用自己的網域上線

deploy.yml 長這樣（參考）

Claude Code 寫的應該跟這份差不多，這是 Vite 官方範例加上 404.html 那一步。看得懂大概就好，不用背。

name: Deploy to GitHub Pages
on:
  push:
    branches: ['main']
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: 'pages'
  cancel-in-progress: true
jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: lts/*
          cache: 'npm'
      - run: npm ci
      - run: npm run build
      - run: cp dist/index.html dist/404.html
      - uses: actions/configure-pages@v6
      - uses: actions/upload-pages-artifact@v5
        with:
          path: './dist'
      - id: deployment
        uses: actions/deploy-pages@v5
片段 意思
on: push push 到 main 時開始。
runs-on: ubuntu-latest 借一台 Linux 雲端電腦。
uses: 用現成的 action。
run: 自己下指令。
permissions 允許這個流程發布到 Pages。

push 之後到 repo 的 Actions 分頁看進度，綠色勾勾代表發布成功，紅色叉叉點進去看錯誤，可以整段貼給 Claude Code。

步驟 3：找到 repo 的 Pages 設定頁

  • ① 打開你的網站 repo（右上角頭像 → Your repositories → 點網站的 repo），點上方最右邊的 ⚙ Settings。看不到就點 ⋯ 找 Settings。
  • ② 左邊選單找 Pages。
  • ③ 往下找到 Custom domain，下一張教你填。

Lovable 建立的 repo 名稱通常和專案名稱相同。只有 repo 的擁有者看得到 Settings。

09 · 課後：用自己的網域上線

步驟 3：填上網域並儲存

  1. 在 Custom domain 的框框輸入 www.你的網域.com。
  2. 按 Save。

這樣填 ✅

www.mybrow.com

不要這樣填 ❌

https://www.mybrow.com/

不要 https://、不要最後的斜線、不要空白。

按完會看到什麼

GitHub 會開始檢查 DNS。這時還沒設 DNS，出現檢查中或失敗都是正常的；做完步驟 4 再回來看就會變成綠色勾勾。

建議主網址用 www。下一步兩種紀錄都設，GitHub 會自動把 你的網域.com 轉到 www.你的網域.com。

用 GitHub Actions 發布不需要 CNAME 檔案，有也會被忽略。先在 GitHub 填好，再去設 DNS，避免網域被別人搶先接走。

09 · 課後：用自己的網域上線

步驟 4：到網域商設定 DNS

登入買網域的網站，找 DNS 設定（可能叫 DNS 管理、DNS Records、Zone）。

類型 名稱 值
A（四筆分開新增） @ 185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
AAAA（可省略） @ 2606:50c0:8000::153
2606:50c0:8001::153
2606:50c0:8002::153
2606:50c0:8003::153
CNAME www 你的帳號.github.io

CNAME 只寫 你的帳號.github.io，不要加 repo 名稱。

先刪掉網域商預設的紀錄（例如停車頁的 A 紀錄）。名稱欄有的網域商寫 @，有的留空代表網域本身。不要新增 * 開頭的萬用紀錄。

09 · 課後：用自己的網域上線

步驟 5：檢查，然後開 HTTPS

在 PowerShell 檢查 DNS：

Resolve-DnsName 你的網域.com -Type A
Resolve-DnsName www.你的網域.com -Type CNAME

第一個要列出四個 185.199… 的 IP；第二個要看到 你的帳號.github.io。DNS 生效最久可能要 24 小時，沒出現先等。

生效後回到同一頁（repo Settings → Pages），在 Custom domain 下面勾選 Enforce HTTPS（網址前面會有鎖頭）。這個選項可能要等到 24 小時後才能勾。

之後照每天的工作循環 push 到 main，GitHub 就會自動重新發布，網站幾分鐘後更新。

卡關怎麼辦

網站一片白

看 Actions 是不是紅叉；vite.config 的 base 要是 '/'。

打開子頁面出現 404

檢查 workflow 有沒有複製 404.html。

出現 DNS check unsuccessful

DNS 還沒生效或紀錄打錯，對照步驟 4 的表。

Enforce HTTPS 不能勾

等憑證發好，最多 24 小時。

如果之後不用 GitHub Pages 了，記得到網域商刪掉這些 A / CNAME 紀錄，免得網域被別人接走。
