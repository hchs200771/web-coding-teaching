05 · 平行工作線

分支讓你安全嘗試

分支像同一作品的另一條時間線，可以先做新功能再合併。

main↗功能分支→合併

任務 · branch

在分支上做新功能

記住命令的方向

分支的基本命令

git switch -c feature/homepage
git status
git switch main
git merge feature/homepage

先切回要接收變更的分支，再執行 merge。

保持每一步看得懂

先提交，再合併

  1. 確認目前分支。
  2. 完成小功能並提交。
  3. 切回目標分支，合併功能分支。
  4. 遇到衝突時逐段整理。

兩種常見合併結果

快轉合併與合併提交

Fast-forward

目標分支沒有新提交時，分支指標直接向前移動，歷史保持直線。

Merge commit

兩邊都有新提交時，Git 建立合併提交，保留兩條工作線的交會點。

是否保留分支形狀，取決於團隊的合併策略。

06 · 改錯時怎麼辦

選對復原方法

先問：改動在哪裡？要保留修改嗎？提交已分享出去嗎？

復原命令會影響不同位置；執行前先看狀態。

看清受影響區域與風險

restore 與 reset 影響哪裡

方式 工作目錄 暫存區 分支指標 風險
restore 檔案 以暫存區內容覆寫 不變 不變 未保存修改會消失
restore staged 不變 取消選取 不變 修改仍在工作目錄
reset soft 不變 保留為已暫存 移動 提交歷史被改寫
reset mixed 不變 清空暫存狀態 移動 提交歷史被改寫
reset hard 覆寫追蹤檔案 重設 移動 未保存修改會遺失
revert 新增反向變更 依提交流程 新增提交 安全保留共享歷史

restore 預設從 index 取回檔案內容。reset 移動目前分支位置；hard 也會覆寫工作檔案。

先確認狀態，再選操作

復原命令範例

git restore index.html
git restore --staged index.html
git reset --soft HEAD~1
git reset HEAD~1
git reset --hard HEAD~1
git revert HEAD

任務 · undo

練習安全復原

保留共同歷史，找回移動過的指標

安全復原與 reflog

已分享的提交，優先用 revert 新增反向提交，不要直接重寫共同歷史。

git revert HEAD

reflog 是本機分支與 HEAD 移動的近期紀錄。若 reset 移走提交，可從 reflog 找到原提交，再建立分支或 reset 回去；它不是遠端備份。

07 · 把作品放到網路上

遠端是另一份 Git 紀錄

本機方便工作，遠端方便備份與協作；同步前先確認狀態。

本機push →遠端← pull本機更新

任務 · remote

連接並同步遠端

同步方向

遠端名稱與同步命令

origin 是慣用的遠端名稱，指向 GitHub 上的儲存庫網址；名稱可以自訂。

git remote -v
git clone https://github.com/demo/my-site.git
git fetch origin
git pull
git push -u origin main

clone 複製 repo；fetch 下載提交但不自動整合；pull 取得並整合遠端更新。

降低衝突的習慣

先同步，再開始工作

  1. 開始前取得最新版本。
  2. 把工作拆成小提交。
  3. 推送前檢查提交內容。
  4. 協作時說明檔案負責範圍。

遠端有你還沒有的提交

推送被拒絕時

常見原因是遠端分支已更新。先 fetch 檢查差異，整合遠端提交並解決衝突，再推送。

git fetch origin
git pull origin main

整合方式依團隊約定；如果有衝突，先完成解決與檢查再推送。

git push

不要直接強制推送覆蓋別人的工作。先確認分支與協作約定。

09 · 把指令看清楚

看懂 commit 圖

下一張是 Git 練習場：選一個題目、打指令，馬上看到 commit 圖怎麼變。

圓圈 = commit

箭頭指向「上一個 commit」。青綠色實心、外面有一圈光暈的是 HEAD 所在的位置；紫色粗框是 merge commit。

標籤 = 指標

藍色膠囊是分支、青綠色「➜ HEAD」是你現在的位置、淡紫色是遠端分支（origin/main）、黃色是 tag。

虛線 = 沒人指著

reset、rebase、刪分支之後，沒有任何標籤指著的 commit 會變成淡淡的虛線圈。

靈感來自高見龍「為你自己學 Git」的 Git 練習場，推薦也去玩玩看。

練習場 · 選題目、打指令、看圖

兩種把分支合在一起的方法

merge 和 rebase 差在哪？

merge

多一個 merge commit，把兩條線接起來。歷史照實保留，最安全。

rebase

把你的 commit 複製到對方後面，歷史變成一直線，但 commit 的 hash 都換新了。

新手原則：已經 push 出去、別人也在用的分支，不要 rebase。不確定就用 merge。

10 · 網頁的旅程

打開一個網站時發生了什麼？

畫面與資料

前端與後端各自負責什麼

前端

HTML 定義結構，CSS 控制外觀，JavaScript 加上互動。

後端

伺服器處理請求，API 接收操作，資料庫保存資料。

一個請求與一份 JSON

API 讓前後端交換資料

前端向 API 發出請求，後端處理後回傳資料；JSON 是常見的資料格式。

GET /api/plants/1
前端HTTP request →API→JSON response 
{ "name": "小葉", "waterToday": true }

網站需要的服務不同

靜態網站與動態網站

靜態

主機直接提供 HTML、CSS、JavaScript 和圖片，適合作品集與文件。

動態

伺服器會執行程式、呼叫 API 或資料庫，適合登入、訂單與個人化資料。

先從靜態頁開始，只有在需求出現時再加入後端。

即時預覽

試著改一個小頁面

修改 HTML、CSS 或 JavaScript，看看預覽如何改變。

瀏覽器
前端HTTPS主機
靜態檔案API後端服務查詢資料庫

網域經 DNS 指向主機；前端可呼叫 API，後端再讀寫資料庫。

GitHub Pages、Vercel 與 Cloudflare Pages 都能部署靜態網站。連接 repo 後，依平台設定建置或發布目錄，再用公開網址檢查首頁與資源路徑。
