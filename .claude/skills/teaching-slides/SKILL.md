# 教學投影片製作重點

從「用 Claude Code 管理你的網站」（web-coding-teaching）整理出來。實作可參考這個 repo 的 `index.html`、`css/style.css`、`js/deck.js`。

## 1. 導覽操作

- 二維結構：章節左右排，同一章的投影片上下排。
  - ← / → 切換章節，並回到該章第一張；↑ / ↓ 切換同一章的投影片。
  - Space / PageDown 往下一張，章節結束就進入下一章；PageUp 往回，可以跨章。
  - Home / End 跳到整份的第一張 / 最後一張。
- Esc（或 o）開啟或關閉章節總覽，點標題就能跳過去。底部也放一顆「章節總覽」按鈕給不熟鍵盤的人。
- 網址記錄位置：`#/章節/投影片`，從 0 起算。重新整理或按上一頁都會留在原本那張。
- 觸控：左右滑切章、上下滑切投影片。
- 輸入框裡不觸發快捷鍵。
- 頁首顯示目前章節名稱，頁尾顯示「第 N 章 · x/y」和進度條。
- 右上角切換深淺色主題：預設跟著系統，手動選擇存在 localStorage，讀寫要包 try/catch。
- 封面要寫出鍵盤操作提示，另外放一張「怎麼使用這份投影片」。

## 2. 頁面尺寸：一張就是一個畫面

- 每張投影片進來就要看得到全部內容，不能要往下捲才看得到。學員不會知道下面還有東西。
- 以一般筆電為準：瀏覽器內容區 1536×864（1920 螢幕開 125% 縮放）。
  - 扣掉頁首 64px、頁尾 77px，投影片可用高度約 723px。
  - 1920×1080 投影機自然放得下。手機（≤750px）允許捲動。
- 放不下時先用 CSS 收緊：用 `@media (min-width: 751px) and (max-height: 1100px)` 縮小間距（1080 高的投影機也套用）、標題和框。內文字級不要小於原本的 90%。
- 還是放不下就拆成兩張。依內容邏輯拆，例如按步驟分開，標題取有意義的名字，例如「安裝 Claude Code：第 2、3 步」。
- 拆頁或插入投影片之後，要檢查所有 `href="#/x/y"` 內部連結，以及「下一張」「下一頁」這類文字引用。
- 每次改完都用 `measure-overflow.html` 量一次，用法見第 7 節。

## 3. 投影片版型（固定的幾種積木）

- **每章第一張是 why-slide**：用「問 / 答」說明為什麼要學，最後一行寫「學完這章，你可以：…」。
- **每章結尾固定兩張**：
  - 「本章重點」：上半 3–5 句快速總結，下半一個框，放小抄（最多 5 個指令或 prompt）或一句 takeaway。有操作的章節放小抄，觀念章節放 takeaway。
  - 「課後練習」：需要動手的章節才加。2–3 題回家自己做得到的題目，寫出完成的樣子，能用 prompt 的就附上。
- **課程分堂**：一堂 2.5–3 小時。實際教學速度大約一張投影片 4–5 分鐘（含操作）。內容超過時，把額外內容標成「自學：」，課堂上跳過。
- **eyebrow**：每張最上面一行小字，格式是 `章節編號 · 章節名`。
- **指令區塊**：一個指令放一個區塊，右上角有複製按鈕，`❯` 提示符號用 CSS 畫，不會被複製到。長指令自動換行，不要橫向捲動。
- **範例輸出**：用另一種底色的區塊（example），讓人一眼分得出「要打的指令」和「會看到的畫面」。
- **prompt-card**：要貼給 AI 的自然語言，跟終端機指令在外觀上分開。
- **作業系統分頁（tabs）**：Windows PowerShell / CMD / macOS 分開放，先寫清楚要貼在哪裡。
- **callout** 放重要提醒，**note** 放次要補充。不要每段都標成重點。
- **圖解用內嵌 SVG**：顏色用 CSS 變數，深淺色主題都要定義；加上 `role="img"` 和完整的中文 `aria-label`。
- **真實截圖**：用編號框標出要點的位置，例如「① ② ③」，旁邊對應步驟說明。
- **休息頁**：寫出「回來後要做什麼」。
- **課末**：放小抄頁、課後練習和資源連結，再加「重看某章」的快速連結。
- **進階內容收進附錄**：有興趣的人自己看，不打斷主線。

## 4. 文案原則

- 繁體中文、短句；一段只講一件事。
- 每個新名詞都配一個生活比喻：
  - commit＝遊戲存檔點，GitHub＝雲端保管箱
  - branch＝草稿本
  - PATH＝電腦找程式的通訊錄
  - 前後端＝餐廳的外場和廚房
- 學員會看到什麼，就照實寫出來。要等很久、畫面不會動、沒有任何訊息的時候，事先說「這是正常的」。
- 錯誤訊息照原文貼出來，再說明它代表什麼、怎麼處理。
- 指令只寫一個版本，不要讓學員自己選。

## 5. 教學原則（給從沒寫過程式的人）

- 先懂名詞和概念，不背指令。
- 有 AI agent 可以用的時候，教「怎麼用一句話請 AI 做」，不教手打指令。
  - 例如：「這個改好了，幫我存一個檔」「網站壞了，幫我回到上一個正常的版本」。
  - 手打指令和模擬練習放到附錄。
- 教學員看懂授權提示：哪些指令可以放心按 Yes，哪些要先停下來問「這會做什麼？」。
- 用一張圖讓學員看到全貌，例如 Git 的工作區 → 暫存區 → 儲存庫 → 遠端，箭頭標上動作名稱。
- 安排「故意弄壞，再救回來」的練習，比示範十個指令更有感。
- 現場常卡關的修正步驟，直接寫成安裝流程的必要步驟，不要另外做成卡關頁。
  - 例如 Windows 裝完 Claude Code 後要把路徑加進 PATH。
  - 指令要寫成重複執行也安全。
- 一次性的設定（安裝、登入、帳號設定）還是讓學員自己打，日常操作交給 AI。
- 時間表標出「時間不夠時先跳過哪些」；也要準備「還沒有訂閱或帳號時，可以先做哪幾章」。

## 6. 技術細節

- 純 HTML、CSS、原生 JS，沒有套件和建置步驟，可以直接放 GitHub Pages。
- 用 ES modules 時，必須透過 HTTP 開啟（例如 `python3 -m http.server`），不能用 `file://`。
- 避開 GitHub Pages 的快取：在 `<head>` 用小段 script 替 CSS 和 JS 網址加上 `?v=時間戳`，並用 import map 對應每個模組。新增 JS 檔時要把檔名加進清單。
- 投影片用 `position: absolute` 疊在一起，靠 transform 移動。不在畫面上的投影片要設 `inert` 和 `aria-hidden`。
- 寫測試檢查：章節數、id 唯一、tabs 對應到存在的面板、本機資源都存在、沒有外部執行期資源。
- 每次改完都 commit 並 push，線上版才會同步更新。

## 7. 量測工具：哪幾張超出畫面

`measure-overflow.html` 放在這個 skill 資料夾。使用方式：

1. 把它複製到投影片專案的根目錄（跟 `index.html` 同一層），並啟動 `python3 -m http.server 8765`。
2. 用 headless Chrome 量測（macOS）：

```sh
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --window-size=1576,904 --virtual-time-budget=6000 \
  --dump-dom "http://localhost:8765/measure-overflow.html?w=1536&h=864" \
  | sed -n '/<pre id="out">/,/<\/pre>/p' | sed 's/<[^>]*>//g'
```

3. 輸出會列出每張超出的投影片：`#/章節/投影片  +超出像素  標題`。
4. 量完記得刪掉複製進專案的那份 `measure-overflow.html`。

工具預設的結構是 `.chapter > .slide`，用 `data-title` 當標題。結構不同時，改檔案裡的選擇器即可。

截圖檢查也用 headless Chrome（`--screenshot`）。要把頁面包在 iframe 裡，並把 `--virtual-time-budget` 設長一點，例如 8000 到 10000；太短會截到切換動畫中途，看起來所有投影片疊在一起。
